# Messages

Every user-visible string is a key. The engine is `@kroma/i18n` (TypeScript) and
`kroma-i18n` (Rust): the same flat `{ "key": "template" }` catalogs, the same
`{name}` interpolation, `$t(other.key)` quoting and CLDR plurals, so a
notification the server renders reads like the screen that shows it.

## One folder per language, one file per namespace

The core catalogs live in `packages/core/src/locales/<locale>/<namespace>.json`.
A namespace is the first segment of a key: `player.play` lives in
`en/player.json` and `fr/player.json`, and nothing else may live there. Keys stay
fully qualified inside the file, so a grep for `player.play` still lands on the
line that defines it.

Nothing lists the files. Adding a namespace is creating `en/x.json` and
`fr/x.json`; adding a key is editing those two files. Everything below follows
from the folder:

- **Discovery.** `catalogs.web.ts` reads the folder with `import.meta.glob`;
  `catalogs.ts` beside it is Metro's half and reads it with `require.context`.
  The shells' Vite configs pick the first, the native bundlers the second.
- **Types.** The Vite plugin (part of `kroma()` from `@kroma/bundler`, which
  every shell config loads) writes `locales/messages.d.ts`, gitignored. It
  teaches `@kroma/i18n` the locales and every namespace's messages. The dev
  server rewrites it when a file appears or disappears; `bun run gen:types`
  does the same without one, and `bun run typecheck` and `bun install` run it
  first. `MessageKey` covers every namespace, and `t('admin.title')`
  autocompletes and typechecks as it always did.
- **The server.** `server/crates/kroma-engine/build.rs` walks the same folder
  and embeds every file; the builder merges a locale's parts and fails the
  build on a key two files both define.
- **The tests.** `catalogs.test.ts` beside the folder checks that every file
  holds only its own namespace, that every language says the same things, and
  that every `$t()` reference resolves.

## How a screen gets its messages

No shell loads the whole catalog up front. Only `lang`, the language names the
locale set reads before anything renders, ships in the entry.

The rest travels with the code. The Vite plugin scans every source module for
string literals that are keys, `'admin.title'` or `` `pipeline.t.${stage}` ``,
and appends an import of each namespace they belong to. That import is a tiny
module handing the engine one loader per locale for the namespace. The moment
the chunk evaluates, the engine fetches the rendered locale's file, and only
that one: a French reader never downloads `en/admin.json`. `useT()` suspends,
through React's `use()`, until what is in flight for its locale has landed, so
the route's pending state shows a moment longer and no key is ever painted.

So a namespace sits in the chunk graph of the code that reads it, one small JSON
request per language actually read: the home route brings `nav` and `content`,
the admin chunks bring `admin`, and a namespace nothing on a page names is never
downloaded. Switching language warms the new locale the same way. There is
nothing to declare and no request to race.

Two cases fall outside the scan, and both still work:

- **A key built at runtime** from a variable, or read from data. Its first miss
  fetches the namespace in that locale through `lazy`, the non-eager glob, and
  the provider redraws when it lands. The key shows for one paint, and nobody
  has to do anything about it.
- **Metro.** A native bundle is one file, so `require.context` registers every
  namespace at boot and nothing is fetched or suspended.

Under vitest the plugin runs eager, so a component test that renders admin copy
has its catalog synchronously and nothing suspends.

A `$t(...)` reference may only quote a key of its own namespace, because
namespaces arrive one at a time. The test enforces it.

## Modules

A module ships `locales/{en,fr}.json` beside its `module.json`; its front end
registers them as a scope, layered ahead of the core catalogs for that module's
pages only. Nothing here changes for modules: a module's catalog is already one
namespace, named by its id.

## Dev tools

The in-app panel (`@kroma/i18n-devtools`, dev server only) marks every string
with the catalog that answered: `[core/player.play]`, `[tv.kroma.torrents/x]`,
`[missing/foo]`, and `[core@en/foo]` where the fallback locale spoke. A key whose
namespace has not landed shows as `missing` until it does.
