The rules below are drawn from Radix, Base UI, Ark UI, shadcn/ui and React Aria,
and from the two facts that make this kit different from all of them: it is
authored against React Native, and it is driven by a D-pad as often as by a
pointer.

## One vocabulary, and it is law

A component that is a set of parts exposes them as a **namespace object**:

```tsx
const Select = { Root, Trigger, Value, Item, Indicator };
export { Select };
```

Not `Object.assign`. The bare name is never renderable, so there is exactly one
way to write every component and no ambiguity about whether `<Select>` means
anything.

The object is not tree-shakable, and that is accepted knowingly: a compound's
parts are nearly always used together, so what it costs here is small - the worst
is `InputGroup` at 4.0 KB gzipped, then `Field` at 0.7 KB, and every other
compound is under 300 bytes. Do not trade the vocabulary for that.

A part name denotes a **role**, never a position, never an input device, never a
boolean spelled as a string. These are the ones you will meet most; the complete
table, and the rule that adding a part means adding a row to it in the same
commit, live in `packages/ui/src/components/DESIGN.md`.

| Part | Means |
| --- | --- |
| `Root` | Owns state, semantics and context. Every compound has one. |
| `Trigger` | The control that opens or toggles the thing. |
| `Panel` | The region a surface owns rather than pins: the body it scrolls, the region it expands, the one it gives the whole stage to. Never the scrim. |
| `Popup` | The floating, styled, animated box. It mounts itself. |
| `Backdrop` | The scrim over inert content. Never `Overlay`, which reads as the popup. |
| `Item` | One selectable or actionable entry, namespaced and never prefixed. |
| `Leading` / `Trailing` | The head and tail of a row. Neither is a second focus stop. |
| `Indicator` | The selected or checked face. **Never pressable.** |
| `Label` / `GroupLabel` | The accessible name; a section heading inside the surface. |
| `Hint` | Help text about a CONTROL, wired to the description role. The one spelling. |
| `Subtitle` | The second line of a HEADING, which is a different role from a hint. |
| `Detail` | The technical particular behind a hint: an error's cause, a code. |
| `Actions` | The controls a surface offers. Always plural, even holding one button. |
| `Value` | The thing being reported. It reports, it never controls. |
| `Media` | The mark that stands for the thing: a glyph, a poster, an avatar. |
| `Addon` | A member of a group nothing can press, shaped like the controls beside it. |
| `Previous` / `Next` | A step through a sequence, named for the direction. |

`Content` and `Viewport` are **banned**: each meant two different things in two
different libraries. `Portal`, `Positioner` and `Anchor` are not parts here -
React Native has no portal, so a `Portal` a caller must remember to write is a
native bug waiting to happen.

## The Root owns; a part is a face

A caller must not be able to arrange the parts into something that lies to a
screen reader or steals a D-pad stop.

- **The Root draws the group role**, the parts carry their own. Nobody can
  compose a `radiogroup` that contains checkboxes.
- **The whole row is the control.** A television has one D-pad stop per row and a
  pointer deserves a hit area the size of the thing it is aiming at. So an
  indicator is a face with nothing pressable about it, and the row carries the
  semantics.
- **A container DECLARES to its parts; it cannot read them.** There is no
  `:first-child` here and Yoga has no `order`. A Root that needs to know its own
  contents walks its direct children once, sorts them, and publishes what it
  learned through context.

## Composition by default; data by named exception

Composition is the default. Take a `data` array plus a render function **only**
when one of these six tests forces it, and say which test in the commit message,
so the exception does not spread by imitation.

| Test | When it forces data |
| --- | --- |
| **T1 Leaf** | The part has no addressable child and exactly one sensible position. |
| **T2 Virtualiser** | The collection can be long enough to need windowing. |
| **T3 Provenance** | The collection comes off the wire: a manifest, a locale catalogue. |
| **T4 Order-is-policy** | The arrangement must vary by locale, direction or platform. |
| **T5 Invalid arrangement** | Some arrangement a caller could write would break semantics. |
| **T6 Identity** | A data collection needs stable ids. |

T2 is the boundary that does not exist on the web, and the one that bites
hardest here: a virtualiser REQUIRES a `data` array, and materialising N children
to hand to one defeats it. React Aria kept children syntax for collections and
paid for it with an entire fake-DOM implementation. That cost is the proof:
children *and* data is not free.

## A face is written as its part

**If a part exists for a face, that face has no prop.** There is one spelling of
a title, a label, a hint, a detail, and it is the part.

This guide used to say the opposite - keep a `label`/`hint` shorthand so the
common row stays one line - and the kit was written that way. It is withdrawn,
for three reasons it paid for first.

- **Two spellings are two APIs.** Every reader learns both, every review allows
  both, and they drift. The shorthand was the road nearly every call site took,
  so the parts were the untested half: `<Callout>`'s `title` and
  `<Callout.Title>` were held in step by a test asserting the two rendered
  byte-identical HTML. That test is what a second API costs, written down.
- **The shorthand hides the shape.** A caller who only ever writes `title=`
  never learns the component is a set of parts, so the first time the design
  wants a badge beside the title they ask for another prop. That is how
  `<PageHeader.Root>` arrived at `title`, `suffix`, `icon`, `subtitle` and
  `actions`: five props forwarding to three parts, two of them there only to
  decorate one of the others.
- **A prop cannot be arranged.** The moment a row is a label AND a badge, the
  shorthand is spent and the call site is rewritten into parts anyway.

```tsx
<Callout.Root tone="danger">
  <Callout.Media name="alert-triangle" />
  <Callout.Title>The file cannot be found</Callout.Title>
  <Callout.Detail>/Volumes/video/Dune.2021.mkv</Callout.Detail>
  <Callout.Actions>
    <Button label="Rescan" size="sm" variant="ghost" />
  </Callout.Actions>
</Callout.Root>
```

### The test, inverted

The old rule's test was: delete the sugar and every behaviour must still be
reachable through the parts. It now runs the other way. **Deleting a prop must
leave nothing unreachable**, and where it would, the answer is a **new part** -
never the prop back.

`<Drawer.Root>`'s header drew a close button; composing `<Drawer.Header>`
silently dropped it, and nine call sites had already hand-rolled their own and
wired `onClose` a second time. The fix was `<Drawer.Close>`, which reads
`onClose` off the shell context and renders nothing where the sheet cannot be
dismissed.

### What is not a face

The rule is about faces. It does not strip the kit of props.

| Stays a prop | Why |
| --- | --- |
| `<Button label>`, `<Chip label>` | A leaf has no parts to write. T1, above. |
| `value`, `disabled`, `onPress`, `icon` | Identity and behaviour, and a glyph is never a part. |
| `<ChoiceList.Root label>`, `<Dialog.Root title>` | It names the thing to assistive tech. That a Root may ALSO draw a default header from it does not make it a face a part exists for. |
| `<Field.Root label>` | The same, required: there is no `Field.Label` part, and `hideLabel` drops the row while keeping the name. |
| `<ListRow.Root label>` | Pure semantics: a row whose middle column says its words through props has no text for the row to be named by. |

### The escape ladder

1. **A named part.**
2. **`render={(props, state) => ReactElement}`**, the function form only, on leaf
   parts only. The caller spreads explicitly.
3. **An exported context hook**. No prop merging at all, and unlike a cloned
   child it survives arbitrary wrapper depth.

### Do not add asChild

`asChild` solves a DOM-only problem: semantics live on the element tag, so a
trigger sometimes has to be an anchor and sometimes a button. Here semantics are
props, so that decision does not exist. What would remain is only the prop merge,
and the merge is worse here than on the web: `style` is a positional array whose
precedence is order, press is a family with focus and hover on top for TV, and a
host ref is a component instance with `measure`, not a node. An implicit merge
over that surface is guesswork.

This is why rung 2 is the function form only. The element form's entire value is
the automatic merge, which is exactly the part that does not survive. Making the
caller spread explicitly is the feature.

## Controlled and uncontrolled

One signature, everywhere: `value` / `defaultValue` / `onValueChange`, and the
same shape for `open`, `checked` and `expanded`.

- **Never `onChange`.** In React DOM `value` plus `onChange` means a form input
  with its own semantics, and reusing it invites `e.target.value`.
- **Controlled-ness is per prop and fixed at mount**, for exactly the reason
  React warns about an input flipping between the two.
- **Value first, details second.** `(next, details)` keeps the 95% call site as
  `onValueChange={setPicked}`.
- **A dismissal carries its reason.** One `onOpenChange(open, details)` beats
  four separate handlers, and there is a reason here the web does not have:
  `reason: 'back'`, the remote's Back button.

## Prop naming

| Use | Not |
| --- | --- |
| `label` | `title`, `text`, `name` - for the accessible name |
| `hint` | `description`, `helperText`; `subtitle` is a different role |
| `icon` | `glyph`, `iconName` |
| `tone` | `color`, `intent`, `status`, `severity` |
| `size` | `scale`, `density` |
| `thickness` | `stroke`, `weight` - the width of a drawn line |
| `disabled` | `isDisabled`, `enabled` |
| `multiple` | `type="multiple"`, `mode="multi"` |
| `onValueChange` | `onChange`, `onSelect`, `onUpdate` |

The law with teeth is the third: **the same role gets the same name in every
component**, or the vocabulary is worthless. `size` is where this kit broke it
worst - it has meant a control size, two distance scales, a diameter and a
thickness.

Everything but the first two is now spelled for what it measures. `thickness` is
the width of anything the kit draws: a `<Divider>`'s rule, a `<Progress>`'s
track, an `<Icon>`'s outline, a `<ProgressRing>`'s arc. `diameter` is a px box on
a control that also wears a shell, which is why `<IconButton>` takes one - `size`
there would have to mean the step and the box at once.

What is left is deliberate. On a control that wears a shell, `size` is the step
in `lib/field-shell` (`sm | md | tv`); on a round leaf - `<Spinner>`,
`<Avatar>`, `<StatusDot>`, `<Icon>`, `<Logo>`, `<ProgressRing>` - it is the
diameter in px, because that is the only measurement the thing has. **A distance
is never `size`.** A component that genuinely has its own ladder names its own
type but keeps the same three words.

## The checklist

Before a component is done:

- [ ] Parts are a namespace object; the bare name renders nothing.
- [ ] Every part name is in DESIGN.md's table, or the table grew in this commit.
- [ ] The Root owns state, semantics and behaviour; no indicator is pressable.
- [ ] A `data` prop, if any, names which of the six tests forced it.
- [ ] No prop writes a face a part exists for: every `label`, `hint`, `title`,
      `subtitle`, `detail`, `actions` or `footer` on a compound is either a part
      or a name nothing draws.
- [ ] Nothing is reachable only through a prop. Where a part could not express
      something, the part grew; the prop did not come back.
- [ ] `value` / `defaultValue` / `onValueChange`; no `onChange`.
- [ ] The shape comes from `lib/field-shell`, not from the component's own paddings.
- [ ] It has a story, and the story passes `variants` so the controls derive.
- [ ] It works under a D-pad and under a pointer without the caller writing
      anything different.
