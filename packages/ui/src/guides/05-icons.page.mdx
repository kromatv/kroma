## The name is the whole API

The slug is Tabler's own export, kebab-cased: `IconPlayerPauseFilled` is
`player-pause-filled`, `IconVolume2` is `volume-2`. `IconName` is a strict
union, so a typo fails to compile in a `.tsx` - this page is MDX, which is not
typechecked, which is the only reason the specimen above could name a glyph that
does not exist. A name arriving from data crosses the border through `hasGlyph`.

```tsx
<Icon name="player-play-filled" size={24} color="accentText" />
```

Pass a palette token to `color` - a raw string is for the few one-off washes -
and leave `thickness` at 1.8 or above, below which an outline disappears at three
metres.

## Searching by letter

The box matches loosely: the letters have to appear in the name in that order,
not next to each other. `chevrn` finds `chevron-right`, `playpause` finds
`player-pause`, and dashes or spaces typed into the box are ignored, so
`player pause` and `playerpause` are the same query.

Hits are ranked, best first:

| What scores | Reads as |
| --- | --- |
| a contiguous run | `pause` in `player-pause` beats the same letters scattered |
| a word boundary | a match at the start, or just after a `-`, is the one meant |
| an earlier match | `search-off` before `world-search` |
| a shorter name | `search` before `search-off`, once the score ties |

The matcher is `lib/fuzzy-search.ts`: a scored subsequence match, no dependency
and no DOM, so the same ranking runs on a television.

## Searching by meaning

A glyph is also reachable through Tabler's own tags, which is how `delete` finds
`trash` and `typography` finds `align-right`. A hit the tags carried says so:
the matched tags are drawn under the name, so a result nobody can explain never
appears.

A tag hit is handicapped rather than kept in a bucket of its own. A name of the
same quality still wins - typing `arrow` gives `arrow-up`, not everything tagged
"arrow" - while a tag matched cleanly beats a name the query merely scatters
through, which is what puts `trash` near the top of `delete` instead of behind a
hundred `device-tablet-…` names.

The category picker comes from the same source: it narrows the grid to one of
Tabler's 41 categories, and searching then works inside it. A `-filled` variant
inherits its base glyph's category and tags, since the catalogue lists only the
outline.

## Where the tags come from

The catalogue is `@tabler/icons`' `icons.json`, read at BUILD time by
`kromaIconCatalog()` (`@kroma/ui/vite/icon-catalog`) and registered with the kit
through `setIconCatalogLoader()`. Only a workbench adds that plugin: it is a
megabyte of metadata for one page, and no product bundle - least of all a
television's - should carry it. Where it is absent the box searches names alone
and the category picker does not appear, which is what the kit's own phone and
TV builds do.

## Both arrive when this page does

A build keeps the glyphs its own sources name and cuts the rest, because a name
resolved at runtime is a name no bundler can shake: 296 of Tabler's 6,250 for
this workbench. A gallery needs all of them, so the browser above fetches the
set and the catalogue as it mounts and spins until they land, two chunks
(490 KB and 119 KB gzipped) that the workbench does not start with and only this
page ever asks for. Everywhere else `<Icon>` draws from the scanned set, exactly
as a client does.

The kit's own phone and TV builds have nothing to fetch: Metro has no dynamic
import to split a chunk off with, so they carry the whole set outright and the
browser draws straight away.

## A page at a time

Tabler ships thousands of glyphs, and drawing them all locks the workbench up
for seconds - far longer on a television - so the grid holds 120 and the rest
are one `Pagination.Root` away. A new query returns to page one.

The grid scrolls inside its own area rather than lengthening the article, so the
bar, the count and the pager stay where they are while a page is read, and a new
page starts at the top of the grid instead of wherever the last one was left. A
television gets the flat grid instead: the tiles take no focus, so a nested
scroller is one the D-pad could never move.
