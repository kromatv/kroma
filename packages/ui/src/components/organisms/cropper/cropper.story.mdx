Frames a picture before it is kept. The Root holds the picture and where it sits behind the frame: a zoom, two offsets and a quarter turn. The image always covers the frame, so there is never an empty edge to crop, and the offsets are fractions of the frame, so the crop drawn on screen is the crop written to a file of any size.

The frame is the whole control. Drag it to pan, turn the wheel or pinch to zoom. It is one D-pad stop: **press** it to take the arrow keys (and plus and minus on a keyboard), press it again to give them back. The tools are parts of their own, so a screen puts them where it wants them.

```tsx
<Cropper.Root src={photo} shape="circle">
  <Cropper.Frame label="Move the photo" />
  <Cropper.Zoom outLabel="Zoom out" inLabel="Zoom in" />
  <Cropper.Rotate label="Rotate left" />
  <Cropper.Reset label="Start over" />
  <Save />
</Cropper.Root>
```

The file comes from `useCropper()`, which is how a button of the caller's own produces it:

```tsx
function Save() {
  const { crop } = useCropper();
  const save = async () => upload((await crop({ width: 512, height: 512 })) ?? original);
  return <Button label="Save" onPress={() => void save()} />;
}
```

`crop()` answers `image/webp` at quality 0.9 unless told otherwise. It resolves `null` where there is no canvas to draw on, which is every native target today, and for a picture the browser may not read back, so a caller always has a fallback.
