Pick one of a few, from a trigger that says what is picked. Composed rather than configured, in Radix's shape: **Root** owns the value and the open state, **Trigger** wears `<TextField>`'s well, **Value** says what is picked and **Item / Indicator** are the row. Where the options appear is the platform's decision: under a D-pad they open in a **Dialog** (a modal is its own view controller on tvOS, so the remote is confined to the options for free), and under a pointer they open as an anchored listbox popover with the full combobox keyboard, meaning arrows, Home/End, type-ahead, Enter to pick and Esc to return to the trigger, announced through `aria-activedescendant`. Every way out is reported: `onOpenChange(open, { reason })` says `select`, `outside`, `escape` or `back`, the remote's Back button.

```tsx
<Select.Root label="Audio track" value={track} onValueChange={setTrack}>
  <Select.Trigger />
  <Select.Item value="truehd" note="lossless">TrueHD 7.1</Select.Item>
  <Select.Item value="aac" note="256 kb/s">AAC Stereo</Select.Item>
</Select.Root>

// Write the row yourself when the sugar is not enough:
<Select.Item value="original" label="Original">
  <Box gap={2} flex>
    <Text variant="body">Original</Text>
    <Text variant="meta" color="textDim">No transcoding</Text>
  </Box>
  <Select.Indicator />
</Select.Item>
```

## Where the options appear

`presentation` decides, and its default asks the platform: a popover under a
pointer, a dialog under a D-pad. Naming one overrides that, which is what these
two scenes do, so both presentations can be read here rather than only the one
this device would have chosen.

<Do>
- Use a `note` for the fact that settles the choice: a bitrate, a codec, a count.
- Wrap it in `<Field.Root>` for the label row. The select is the control, not the form row.
- Give a composed row a `label`: it is what the trigger and assistive tech read.
</Do>

<Dont>
- Reach for it with two options. Two Chips show both answers at once.
- Put dozens of items in one: past a screenful it is a search problem, not a pick.
</Dont>
