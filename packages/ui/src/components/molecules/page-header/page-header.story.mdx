  args: { title: 'Users', suffix: '12', subtitle: 'Accounts and invitations' },
  controls: { title: 'text', suffix: 'text', subtitle: 'text' },
  render: ({ title, suffix, subtitle }) => (
    <PageHeader.Root>
      <PageHeader.Title suffix={suffix || undefined}>{title}</PageHeader.Title>
      {subtitle ? <PageHeader.Subtitle>{subtitle}</PageHeader.Subtitle> : null}
      <PageHeader.Actions>

    </PageHeader.Root>
  ),
});

A page's opening line: the display title (with an optional quiet `suffix` - a count, a category), a subtitle under it, and the page-level actions pinned to the other end. The title is a real **heading** to assistive tech, so a screen reader can land on it.

Composed: `Root` owns the row, and `Title`, `Subtitle` and `Actions` are named parts. `Root` sorts its direct children once, so an `Actions` reaches the far end wherever it was written and everything else joins the title column - Yoga has no `order` to fix it afterwards.

```tsx
<PageHeader.Root>
  <PageHeader.Title icon="flame">Trending</PageHeader.Title>
  <PageHeader.Subtitle>What the world is watching</PageHeader.Subtitle>
  <PageHeader.Actions>
    <Button variant="primary" icon="plus" label="Invite" onPress={invite} />
  </PageHeader.Actions>
</PageHeader.Root>
```
